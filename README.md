# VHS Studio

**Give digitised family recordings a new lease of life.**

A Windows desktop app focused on VHS restoration: correct interlacing, enhance
details, find on-screen dates and prepare precise, traceable AI-assisted reviews.
The interface is available in **English and German**.

> **Early preview — vibe-coded with AI assistance.** This project is being built
> collaboratively with coding agents. It is not professionally audited restoration
> software. Test on copies of your footage and inspect the results. Contributions,
> reproducible bug reports and careful reviews are welcome.

## What it does

| Step | Purpose |
| --- | --- |
| QTGMC deinterlacing | Reconstruct smooth progressive frames from interlaced VHS footage. |
| BWDIF alternative | Offer a faster deinterlacing option. |
| OpenProteus 2× | Enhance resolution using a local Vulkan-capable GPU. |
| Date OCR | Read visible camera dates at 0.25, 0.5, 1, 2 or 4 samples per second. |
| AI review write-back | Preserve raw readings and separately record verified dates, scene boundaries, uncertainty and reviewer/model attribution. |
| Local automation | Use the same engine through standard MCP or a JSON command-line interface. |

A VHS tape can contain recordings made on many different days or even years.
After digitisation, they may all be in one file. Date OCR helps locate those
changes so that the footage can be reviewed and split later. **The app does not
automatically cut footage. OCR and camera clocks can both be wrong.**

## Downloads

Each published Windows release is intended to offer two packages:

* **Portable ZIP:** the executable and its verified external components, ready
  for offline use after extraction.
* **Standalone EXE:** includes Python, the interface and small application
  dependencies; missing large components are fetched from pinned upstream
  releases into the current user's application-data folder.

Release packaging and automatic updates are under active development in this
initial source preview. A source-code ZIP generated by GitHub is **not** the
portable Windows application. Only use explicitly published application assets.

Downloads come from original upstream sources, not repackaged dependencies in
this Git repository. FFmpeg Windows release builds are supplied by Gyan, a
provider linked from ffmpeg.org. VapourSynth and its plugins use versioned PyPI
wheels. Archive hashes, extracted file hashes and expected sizes are pinned in
`runtime-manifest.json`. No development snapshots are selected at runtime.

## Workflow

1. Select the folder containing your digitised recordings.
2. Choose an output folder and enable the desired restoration steps.
3. Check the files and review the proposed queue.
4. Start restoration and follow progress in Files, Log or Date findings.
5. Inspect the resulting video and any OCR findings.

**Export mode preserves input files.** Archive mode is optional and moves prior
versions into archive subfolders after verification. Read its description before
using it. A process lock prevents overlapping writes to the same output archive.

Settings are remembered locally. Optional login startup uses a saved snapshot
of your configuration, works without a visible window and does not require
administrator rights. It is disabled until explicitly enabled in the app.

Resource modes adapt to detected CPU cores. Background/Gaming lowers CPU
priority, limits cores and inserts pauses between GPU frames. It is not a
driver-enforced GPU percentage limit and cannot guarantee gaming frame times.

## Date findings and AI review

OCR data and logs are stored under the selected destination:

```text
_Verwaltung/VHS-Studio/
  VHS-Studio.sqlite3
  OCR-Fundstellen.json
  OCR-Fundstellen.csv
  Lauf-*.jsonl
```

SQLite is authoritative. Raw OCR observations remain intact. Reviews are
append-only and include a decision, optional confirmed date and boundary,
uncertainty, evidence, provider and known model name. Attribution is self-reported,
not independently authenticated. Conflicting concurrent review writes are rejected.

Copy the AI review prompt from Date findings and give it to an agent with local
file access. It explains frame inspection and the `submit_ocr_review` write-back
tool. A web chat without local tools cannot modify your files merely by receiving
the prompt. The open table refreshes from SQLite and shows review results;
double-click a row for evidence and history.

The app does not upload footage to an AI provider. If you choose an external AI,
that provider's own tools, permissions and privacy policy determine what it sees.

## MCP and scripting

The executable supports local stdio MCP:

```json
{
  "mcpServers": {
    "vhs-studio": {
      "command": "C:\\path\\VHS Studio.exe",
      "args": ["--mcp"]
    }
  }
}
```

The configuration location depends on your AI client. No network listener or
automatic client registration is created. Alternatively, an agent with shell
access can use `--describe` and `--api request.json response.json` without an MCP
entry. See [AI-CONTROL.md](AI-CONTROL.md) for schemas, sequencing and safety rules.
GUI jobs and API/MCP jobs are currently tracked separately.

## Requirements

Windows 10/11 x64 is the current target. QTGMC depends on supported CPU features;
OpenProteus additionally needs a suitable Vulkan graphics driver. Date OCR uses
Windows OCR and an available recognition language. Unsupported or untested
machines should not be assumed to work solely because they run Windows.

Python is bundled in application releases. A system-wide Python installation,
administrator access, a Windows service or an AI subscription is not required
for local restoration. AI review tools may have their own requirements.

## Development and privacy

Python 3.12 x64 is the current development target. Build scripts and the pinned
upstream manifest are included; release automation is being completed. Build
outputs, downloaded dependencies, weights, local settings, videos, databases and
logs are excluded from Git. Do not submit family footage or personal paths in
public issue reports.
